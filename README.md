# 吉他五线谱闪卡

一个纯前端的简体中文 PWA，用来练习**高音谱号上的音符**，并把它们和**音名、固定唱名、指板位置**对应起来。

- 标准调弦、第一把位开始，逐步扩展到第二至第五把位和全指板 12 品。
- 音符位置全部由「弦号 + 品位」推算，不在数据里手写音名或谱面坐标。
- 使用 VexFlow 绘制高音谱表，低音弦的下加线由 VexFlow 自动绘制；指板是自写的 SVG。
- 无后端、无音频文件；进度存在 `localStorage`，可添加到手机桌面并离线使用。
- 线上地址：<https://guitar-staff-flashcards.pages.dev>（Cloudflare Pages，连接 GitHub 自动发布）。

## 打不开？先看这里

**直接双击 `index.html` 看不到内容**，是因为浏览器在 `file://` 下会以 CORS 为由拦截 ES module 脚本，控制台会报 `blocked by CORS policy`。这不是项目缺文件。

现在项目对两种打开方式都做了处理，任选一种：

### 方式一（推荐）：双击 `启动.command`

1. 在文件夹里双击 **`启动.command`**。
2. 会自动启动本地服务器并打开 <http://127.0.0.1:8080/>。
3. 这个终端窗口开着，服务器就在跑；关闭窗口即停止。

如果 macOS 提示「无法打开，因为来自身份不明的开发者」：在文件上 **右键 → 打开 → 打开** 一次即可。也可以在终端里执行：

```bash
cd ~/Desktop/guitar-staff-flashcards
bash 启动.command
```

这种方式是完整的 PWA：可以离线、可以「添加到主屏幕」、Service Worker 正常工作。

### 方式二：直接双击 `index.html`

现在也能打开。`index.html` 检测到 `file://` 时会改用预先生成的传统脚本 `js/app.file.js`，绕过模块限制。

代价（`file://` 的浏览器限制，不是应用 bug）：

- 没有 Service Worker，不能离线，也没有「安装到主屏幕」。
- 部分浏览器（尤其 Safari）在 `file://` 下会限制 `localStorage`，学习进度可能无法跨次保留；应用会提示并退化为内存存储。
- `manifest` 不会加载（应用只在 `http(s)` 下注入它，避免控制台报错）。

所以长期使用还是建议方式一，或部署到静态托管（见「部署到 Cloudflare Pages」）。

### 方式三：命令行

```bash
cd guitar-staff-flashcards
npm start          # 或 python3 -m http.server 8080
# 打开 http://127.0.0.1:8080/
```

> 如果你之前运行过 `npm start` 现在打不开，先确认那个终端还开着；终端关闭后服务器就停了。`启动.command` 会自动处理这种情况。

### 还是打不开？按顺序检查

1. **确认打开的是新文件**：旧标签页按 `Cmd + Shift + R` 强制刷新。若之前装过 Service Worker，新版本会提示「新版本已准备好 · 刷新」。
2. **看控制台第一个红色错误**：`blocked by CORS policy` → 你还在用旧的 `file://` 方式，请用 `启动.command`；`404 app.js` → 文件夹不完整，`js/` 要在 `index.html` 旁边。
3. **确认文件都在**：`index.html`、`js/app.js`、`js/app.file.js`、`vendor/vexflow.js`、`css/styles.css` 缺一不可。
4. **端口被占用**：`启动.command` 会自动在 8080–8099 里找空位；也可以 `PORT=9000 bash 启动.command`。

## 本地运行

应用本身不需要 `npm install`，也没有构建步骤。

```bash
cd guitar-staff-flashcards
npm start
# 打开 http://127.0.0.1:8080/
```

`npm start` 会运行 `scripts/serve.mjs`（Node 18+，零依赖）。也可以使用：

```bash
python3 -m http.server 8080
```

### 改了 js/ 源码之后

`js/app.file.js` 是 `js/*.js` 的自动生成副本，供双击打开使用。改完源码后运行：

```bash
npm run build:file
```

`npm test` 会检查这个文件是否过期，过期会直接失败并提示重新生成。

### 可选开发依赖

```bash
npm install
npm run test:ui        # jsdom + VexFlow 真实渲染与完整流程
npm run check:browser  # 真实 Chrome 验收（需要本机 Chrome）
npm run check:audio    # 校验「听一下」播放的是实际音高
npm run check:file     # 用 file:// 打开，验证双击路径可用
npm run check:mobile   # 模拟 iPhone 走局域网地址，验证手机路径
npm run build:static   # 生成静态发布目录 dist/
npm run check:deploy   # 发布产物验收：答题、刷新保留、导出/导入、离线
npm run check:layout   # 三模式布局：位置一致、谱面不裁切、指板对称、小屏无溢出
```

`jsdom` 与 `playwright-core` 只用于可选测试，不会进入应用运行时代码，也不会被 Service Worker 缓存。

## 手机端如何打开

### 方案 A：同一 Wi-Fi，直接访问（最快，1 分钟）

适合先试试手感。电脑和手机连**同一个 Wi-Fi**，然后：

1. 在电脑上双击 `启动.command`（或在终端 `npm start`）。
2. 终端会直接打印手机地址，例如：

```text
  电脑打开：http://127.0.0.1:8080/
  手机打开：http://192.168.1.100:8080/
            （手机与电脑需连同一个 Wi-Fi）
```

3. 在手机浏览器地址栏输入这个 `192.168.x.x:8080` 地址。

也可以在电脑浏览器打开应用，进入**设置 → 在手机上打开**，那里会显示同样的地址，点「复制地址」可以发到手机（微信/备忘录/隔空投送都行）。

**这个方式能得到什么**：完整的关卡、谱表、指板、答题、间隔重复、音频，学习进度存在手机本地。

**这个方式缺什么**（浏览器规定，不是应用缺陷）：

| 功能 | 局域网 http:// | HTTPS |
| --- | --- | --- |
| 答题、音频、进度 | ✅ | ✅ |
| 离线缓存 | ❌ | ✅ |
| iOS「添加到主屏幕」 | ⚠️ 可添加，但无离线 | ✅ |
| Android 安装 PWA | ❌ 只是普通快捷方式 | ✅ |

原因是 Service Worker 只在**安全上下文**（HTTPS、`localhost`、`127.0.0.1`）下可用。`192.168.x.x` 属于普通 HTTP，浏览器会拒绝注册。

应用检测到这一点时不会再尝试注册（避免控制台报错），而是在设置页标注「需联网访问」，并解释原因——不假装成功。

### 方案 B：部署到 HTTPS，真正装到桌面（推荐日常使用）

手机要「添加到主屏幕 + 离线」，必须有 HTTPS。推荐用 Cloudflare Pages 连接 GitHub 仓库（见下一节）：

1. 把代码推到 GitHub。
2. 在 Cloudflare Pages 里连接这个仓库，构建命令 `npm run build:static`，输出目录 `dist`。
3. 等半分钟，拿到 `https://xxx.pages.dev` 地址。
4. 把地址发到手机，用浏览器打开。

装到桌面：

- **iPhone / iPad（Safari）**：点底部「分享」→「添加到主屏幕」→「添加」。之后从桌面图标打开，是全屏、无地址栏的独立应用。
- **Android（Chrome）**：右上角菜单 →「安装应用」或「添加到主屏幕」。

首次联网打开后，脚本、图标、字体和样式都会进入缓存，之后断网也能用。详见下一节。

### 方案 C：不想部署，只想在手机上看

把整个文件夹通过隔空投送 / iCloud Drive / 微信文件传输发到手机，用支持本地 HTML 的浏览器打开 `index.html`。

- Android 的 Chrome 可以打开 `file://`，会走内置的兼容包，能答题。
- iPhone 的「文件」App 预览对本地 HTML 支持很差，通常需要第三方浏览器，体验不稳定。
- 这条路径同样没有 Service Worker 和「添加到主屏幕」。

所以如果打算长期练，还是用方案 B。

### 连不上时排查

1. **确认同一网络**：手机和电脑都连同一个 Wi-Fi；不要在「访客网络」（通常会隔离设备）。
2. **确认地址和端口**：终端打印的 `192.168.x.x` 才是手机要用的；`127.0.0.1` 在手机上指的是手机自己。
3. **macOS 防火墙**：系统设置 → 网络 → 防火墙，如果开着，允许 `node` 接受传入连接。
4. **公司/学校网络**：可能禁止设备互访，换手机热点试试（电脑连手机热点，再用电脑的局域网地址）。
5. **IP 变了**：路由器重新分配地址后，重启一次 `启动.command`，用新打印的地址。
6. **手机端仍是旧页面**：下拉刷新，或换成无痕窗口。

## 部署到 Cloudflare Pages（免费 xxx.pages.dev）

项目是纯静态站点，不需要打包器，但需要一个构建步骤把运行文件整理进 `dist/`。

仓库里的约定：

- 构建命令：`npm run build:static`（等价于 `node scripts/build-static.mjs`）
- 输出目录：`dist`
- Node 版本：`.nvmrc` 固定为 20
- 构建脚本零依赖，只用 Node 内置模块，因此**不需要 npm install**
- `dist/` 和 `*.zip` 已写进 `.gitignore`，由托管平台构建，不入库

仓库里**没有** `netlify.toml`、`wrangler.toml`、`vercel.json` 或 `_redirects`：发布参数全部在托管平台后台设置，换平台不用改代码。缓存头写在构建生成的 `dist/_headers`，Cloudflare Pages 与 Netlify 都识别这个文件。应用使用 `#/` 哈希路由，不需要 SPA 兜底重定向。

### 第一步：把代码推到 GitHub

如果还没有仓库，在 `guitar-staff-flashcards/` 目录里执行：

```bash
git init -b main
git add -A
git commit -m "吉他五线谱闪卡 1.2.0"
```

然后在 GitHub 新建一个空仓库（**不要**勾选 README / .gitignore），复制它给出的地址：

```bash
git remote add origin https://github.com/<你的账号>/<仓库名>.git
git push -u origin main
```

推送前可以确认提交内容里没有 `node_modules/`、`dist/`、`*.zip`、`tests/tmp/`：

```bash
git status --short
git ls-files | wc -l      # 约 60 个源码文件，不含依赖与产物
```

### 第二步：在 Cloudflare 连接仓库

1. 打开 <https://dash.cloudflare.com> 注册 / 登录（免费，不需要绑卡）。
2. 左侧 **Workers & Pages** → **Create** → **Pages** → **Connect to Git**。
3. 授权 GitHub，选中刚才的仓库，分支选 `main`。
4. 构建设置填：

   - **Framework preset**：`None`
   - **Build command**：`npm run build:static`
   - **Build output directory**：`dist`
   - **Root directory**：留空（仓库根目录）

5. 可选但建议：在 **Settings → Environment variables** 加一条
   `SKIP_DEPENDENCY_INSTALL = 1`。
   构建脚本不需要任何依赖，跳过 `npm install` 能把构建时间从几十秒压到几秒，也避免安装 `playwright-core` 这类只用于本地测试的包。
6. 点 **Save and Deploy**。

### 第三步：拿到网址

- 地址由项目名决定：项目名叫 `guitar-staff-flashcards`，网址就是 `https://guitar-staff-flashcards.pages.dev`。
- Pages 的 `*.pages.dev` 子域和项目名绑定，控制台没有「重命名项目」入口。想换网址只能**新建一个用新名字的项目**，确认新址可用后再删掉旧项目（否则同一个仓库会被构建两次）。
- 想用自己的域名：**Custom domains → Set up a domain**，需要另行购买域名。
- 之后每次 `git push` 到 `main`，Cloudflare 会自动重新构建并发布，通常 30 秒到 1 分钟生效。

### 不建仓库的备选：直接上传

Cloudflare Pages 也支持 **Upload assets**：本地运行 `npm run build:static`，把 `dist` 文件夹整体拖进去即可。这种方式不跟随代码更新，只适合临时预览。

### 国内访问

- 免费 `*.pages.dev` 子域名可用，不需要买域名。
- 国内访问 Cloudflare 也可能偶发偏慢或需要重试，但通常比 Netlify 稳定；应用加载后由 Service Worker 缓存，后续打开会明显变快。

### 部署后确认

- 首次打开后进入「设置 → 关于」，应显示「离线可用」（Service Worker 已接管）；未接管时会显示「需联网访问」，刷新一次再看。
- iPhone / iPad 用 Safari「分享 → 添加到主屏幕」；Android Chrome 菜单里「安装应用」。
- 不需要手动改缓存版本：`npm run build:static` 会按 `dist/` 内容哈希写入 `CACHE_NAME`，内容一变版本就变，老用户会收到更新提示；内容没变则不会反复提示。

### 安装到手机桌面

- **Android / Chrome**：打开菜单，选择「安装应用」或「添加到主屏幕」。
- **iPhone / iPad**：用 Safari 打开，点分享按钮，选择「添加到主屏幕」。

首次联网打开后，应用图标、脚本、字体和样式都会被缓存，之后可离线使用。

## 音乐规则

### 调弦与记谱

标准调弦的实际音高：

| 弦号 | 空弦 | 实际音高 | MIDI |
| --- | --- | --- | --- |
| ⑥ | E2 | E2 | 40 |
| ⑤ | A2 | A2 | 45 |
| ④ | D3 | D3 | 50 |
| ③ | G3 | G3 | 55 |
| ② | B3 | B3 | 59 |
| ① | E4 | E4 | 64 |

吉他谱比实际音高高八度记谱：

```text
writtenMidi = actualMidi + 12
谱上音高 = 实际音高 + 12 个半音
```

因此：

- ⑥弦空弦实际是 E2，谱上画 **E3**，在谱表下方需要 **3 条下加线**（C4、A3、F3）。
- ⑤弦 3 品实际是 C3，谱上画 **C4**，是 **1 条下加线**（中央 C）。
- ①弦 12 品实际是 E5，谱上画 **E6**，在谱表上方需要 **3 条上加线**。

### 唯一数据源

题库只存 `{ string, fret }`，其余全部由 `music.js` 推算：

```text
弦号 + 品位
  → 实际 MIDI
  → 谱上 MIDI（+12）
  → 音名 / 固定唱名 / 谱面自然音级步数
  → 五线谱位置、加线数量
```

### 固定唱名

`C=do, D=re, E=mi, F=fa, G=sol, A=la, B=si`。

升降号按设置统一写成升号或降号：

- 升号：`C♯ D♯ F♯ G♯ A♯`，唱名 `do♯ re♯ fa♯ sol♯ la♯`
- 降号：`D♭ E♭ G♭ A♭ B♭`，唱名 `re♭ mi♭ sol♭ la♭ si♭`

同一个品位不会混用两种写法。例如 ⑤弦 4 品在升号模式下显示 C♯4，在降号模式下显示 D♭4；两者 MIDI 相同，但五线谱上的位置会按实际拼写变化。

### 熟练度的「音」怎么算

学习进度按**谱面音高**记录，键名为 `w<writtenMidi>`（例如 `w60` 表示谱上 C4）。同一个音在不同弦/品出现时共享熟练度；一组题内也按谱面音高去重。

| 1 | 第一把位 · 1–3 弦 | ①–③ | 0–3 | 自然音 | 不显示 |
| 2 | 第一把位 · 4–6 弦 | ④–⑥ | 0–3 | 自然音 | 不显示 |
| 3 | 第一把位 · 六弦混合 | ①–⑥ | 0–3 | 自然音 | 不显示 |
| 4 | 第一把位 · 含升降号 | ①–⑥ | 0–3 | 全部音 | 不显示 |
| 5 | 第二把位 | ①–⑥ | 2–5 | 全部音 | 部分显示 |
| 6 | 第三把位 | ①–⑥ | 3–6 | 全部音 | 部分显示 |
| 7 | 第四把位 | ①–⑥ | 4–7 | 全部音 | 部分显示 |
| 8 | 第五把位 | ①–⑥ | 5–8 | 全部音 | 部分显示 |
| 9 | 全指板 · 自然音 | ①–⑥ | 0–12 | 自然音 | 总是显示 |
| 10 | 全指板 · 含升降号 | ①–⑥ | 0–12 | 全部音 | 总是显示 |
| 11 | 混合挑战 | ①–⑥ | 0–12 | 全部音 | 随机显示 |

把位定义：第 N 把位 = 每根弦的第 N 到 N+3 品。第一把位另外包含 0 品（空弦）。

### 解锁

- 第一关默认解锁。
- 完成当前关的所有**不同谱面音高**都达到第 3 级熟练度（共 5 级），且**最近一组正确率 ≥ 90%**，就解锁下一关。
- 5 级制下，一个音要连续答对两次（1 → 2 → 3）才算达标，所以通常需要 2–3 组全对。
- 解锁状态一旦达成会保留；之后某组发挥不佳不会把已解锁关卡重新锁上。
- 设置中的「解锁全部关卡」可跳过解锁条件自由练习；关闭后恢复按完成度解锁。

### 进度怎么显示

- **掌握进度（百分比）**：每个音从 1 级升到达标线 3 级算满，超过 3 级不再加分；没练过的音计 0。关卡卡片、结果页「本关进度」和首页「全指板进度」都用这一个口径，只是范围不同（本关 / 全指板 37 个音）。
- **达标（x / y）**：达到 3 级的音数，和解锁规则一致。
- **弱项练习**：只收答过至少 2 次、并且答错过或练了 4 次以上仍没达标的音（已达标但总正确率低于 70% 的也算）；刚练完第一组、一次没错的音不算。

### 每组题数

标准是 10 张。第一关只有 8 个不同音、第二关 9 个，因此这两关的每组题数会自动缩小为 8 / 9，保证组内不重复出同一个音。结果页会显示实际题数。

## 答题模式与设置

### 三种作答方式

1. **唱名**（默认）：固定唱名按钮；按关卡决定 7 / 12 个。
2. **音名**：7 个自然音按钮；含升降号的关卡显示 12 个半音按钮。
3. **指板**：显示 6 弦指板，点击位置作答。范围随关卡变化，全指板关卡可左右滑动。

默认是唱名，降低「先背音名」的门槛；设置里随时可以切回音名或指板。从 1.1 升级时，仍停留在旧默认「音名」的设置会一次性跟随新默认改为唱名（`js/storage.js` 的 `SETTINGS_VERSION`），之后手动选音名不会被再改。

### 显示内容

设置中可选择答题后显示：

- 只音名
- 只唱名
- 两者同时（例如 `E · mi`）

答题按钮仍由「答题模式」决定，不会被显示设置改写。

### 弦号提示

每道题都带 `displayString` 属性：

- **不显示**：指板题中，任何能发出该谱面音高的位置都算对。
- **显示**：谱上音符旁出现带圈数字（①–⑥），指板题只接受该弦上的位置；点其他弦算错，并高亮正确位置。
- 设置里的「自动 / 总是显示 / 从不显示」可以覆盖关卡默认概率。手机端会在谱表下方再显示一个「指定弦」提示，方便确认。

### 其他设置

- **升降号写法**：升号 / 降号。
- **主色**：6 个预设色 + 自定义颜色，只影响主题，不影响谱面语义。
- **解锁全部关卡**：练习模式。
- **重置学习进度**：清除熟练度、完成度和统计，保留设置。
- **清除全部数据**：设置和进度一起清除。

## 学习逻辑

- 一组 10 张题（小关卡自适应为 8/9 张），组内按谱面音高去重。
- **到期优先**：每个音都有「下次该复习」的时间。出题时先安排到期和过期的音，不够 10 张才用熟练度加权补足。从未练过的音视为立即到期。
- 答错立即显示正确答案，并在指板上用绿色圈出正确位置；这道题会在 **3–5 题后**再出现一次。
  - 若剩余题目不足 3 道，会按实际剩余题数尽快出现；反馈会显示实际间隔。
  - 同一张题最多重做 **2 次**。再错就放过它，记入「仍未掌握」，不让一个音把整组卡死。
- 熟练度 1–5 级，间隔递增：

| 级别 | 含义 | 答对后下次复习 |
| --- | --- | --- |
| 1 | 刚学过 | 当天 |
| 2 | 见过 | 1 天后 |
| 3 | 熟悉（达标） | 3 天后 |
| 4 | 牢固 | 7 天后 |
| 5 | 长期 | 16 天后 |

  - 答对：`1 → 2 → … → 5`（最高 5 级）。
  - 答错：**降一级**，不是归零；1 级时保持不变，并立即到期。
  - 抽题权重：1 级 8、2 级 5、3 级 3、4 级 2、5 级 1；过期越久再乘最多 3 倍的紧迫度。
- **音高和指板位置分开记**：`w60` 记「谱上 C4 认得怎么样」，`w60@3` 记「C4 在③弦上找得怎么样」。同音异位是两次不同的练习，不会互相冒充。
- 正确率按**每张题的第一次作答**计算，重做不会刷高正确率。
- 不设倒计时；每题从出现到作答的时间会被记录，结果页显示本组平均用时。
- 答错不会震动、不会自动播放声音。只有用户点击「听一下」时才播放该题的实际音高。

### 弱项练习

练过一组之后，首页会出现「弱项练习」入口：

- 从学习记录里挑出还没达标（< 3 级）或曾经答错的音，最多 12 个。
- 只用你练过的音，不会突然冒出完全没接触过的内容。
- 全部是自然音时只给 7 个按钮。
- 弱项练习不推进关卡完成度，只影响这些音的熟练度。

### 结果页

- 正确率、平均用时、本组题数、重做次数。
- 最容易错的 3 个音（按本组错误次数），附缩略五线谱与位置。
- 「仍未掌握」区块：重做两次仍错的音，已自动收录进弱项。
- 解锁横幅或下一关条件（平均熟练度、达标数、正确率）。
- 「再来一组」「返回关卡」；弱项练习则是「再练一组弱项」。

### 键盘快捷键（桌面）

| 按键 | 作用 |
| --- | --- |
| `1`–`9` | 选择对应序号的答案 |
| `空格` / `回车` | 看完反馈后进入下一题 |
| `L` | 听一下当前音 |

在输入框、对话框打开时不生效。

## 数据存储

只使用 `localStorage`，没有网络请求：

- `gsf:settings:v1`：答题模式、显示内容、升降号写法、弦号提示、主色、手动解锁；`version: 2` 表示默认已切到唱名。
- `gsf:progress:v1`：进度模型 v2，包含
  - `notes`：按谱面音高的熟练度、正确/错误次数、`lastSeenAt`、`dueAt`；
  - `positions`：按「音高 + 弦号」的指板位置熟练度，字段同上；
  - `levels`：各关的最近一组、完成时间、正确率；
  - `totals` 与最近 30 组历史。

旧版本（3 级制、没有 `dueAt`）的数据会在读取时自动迁移：等级原样保留，`dueAt` 按 `lastSeenAt` 和当前级别的间隔推算。不需要手动处理。

### 备份与恢复

设置页的「学习数据」提供：

- **导出备份**：下载一个 `吉他五线谱闪卡-备份-YYYY-MM-DD.json`，包含设置与全部熟练度。
- **导入备份**：校验文件确实是本应用的备份后，覆盖当前进度（会二次确认）。

换手机、清浏览器缓存前建议先导出一份。导入会拒绝格式不符或损坏的文件，并给出中文原因。

所有数据只在本机，没有账号、没有同步。

## 音频

`audio.js` 用 Web Audio 合成声音：

- 基频是**实际音高**（不是谱上高八度），例如 ⑥弦空弦播放 E2 约 82.4 Hz。
- 正弦基频 + 少量二次/三次谐波，带柔和起音和指数衰减。
- 叠了一层 14 ms 的带通噪声瞬态，模拟拨片触弦的「哒」声，比纯正弦更像拨弦。瞬态绕开起音包络，音量很低，不会刺耳。
- 不加载任何音频文件。
- 低音 E2 在手机小喇叭上可能偏弱，这是物理限制；戴耳机更明显。

## 实现说明与取舍

- **VexFlow 5.0.0 已内置**：`vendor/vexflow.js` 约 1.1 MB，字体以 data URI 内嵌，不依赖 CDN。许可证见 `vendor/VEXFLOW-LICENSE.txt`。
- **谱表**：只画高音谱号单音；VexFlow 自动处理线、间、加线和升降号。弦号徽标是在同一个 SVG 上追加的圆圈数字，避免依赖特殊字体，位置在符头右侧 34px，不会压住音符。
- **谱面卡片高度**：答题页用 `viewBox: { y: 33, height: 139 }` 把画布收紧到真实笔画范围（最高音 E6 的上加线顶到 y≈41，最低音 E3 的三条下加线底到 y≈163.5）。VexFlow 的 clef 字形包围盒比实际笔画大得多，直接按 `height` 排版会上下各空出约 50px；收紧后卡片从约 230px 降到约 158px（390 宽），三种作答模式共用同一套参数，切换时不跳动。
- **指板**：完全自写 SVG，6 弦横向排列，1 弦在上、6 弦在下；4 品窗口固定宽度，12 品窗口横向滚动；每个位置都有键盘可聚焦的点击区域。答错时，如果正确位置在屏幕外，指板会自动滑到它。
  几何由 `computeFingerboardGeometry` 统一计算：指板矩形在「①弦之上」与「⑥弦之下」留出相等的 `padY`，六根弦因此在矩形内垂直居中（早先是上方 14px、下方 41px 的偏置）；弦号用 `dominant-baseline: central` 与弦线精确对齐；触控矩形高等于弦间距（27 单位），上下相邻正好相接、不重叠。
- **主题**：Material 浅色、主色可配置；用 JS 混合颜色而不是 `color-mix()`，兼容更多手机浏览器。
- **响应式**：手机竖屏优先；≥1024px 时首页 hero 变双栏、关卡列表两列，避免桌面上大片空白。
- **正确率与解锁**：按第一次作答计算；解锁后保持。手动解锁是练习模式，不会伪造完成度。
- **熟练度与间隔**：5 级制 + `dueAt` 到期时间，答错降一级而不是归零。间隔是固定表（0/1/3/7/16 天），没有用 SM-2 之类的动态因子——对初学阶段够用，也更容易解释给用户。
- **音高 vs 位置**：`notes` 和 `positions` 分开存。指板题同时更新两者，因为认谱和找位置都参与了；但位置熟练度只由指板题更新，不会因为练音名就把「第 8 品」标成熟练。
- **小关卡题数**：第一关 8 个不同音、第二关 9 个，因此组题数自适应为 8/9；这是为了同时满足「10 张一组」和「组内不重复同一个音」而做的取舍。
- **重做间隔**：队列剩余不足 3 题时，错题无法严格等到 3–5 题后再出现；会放到队尾/紧接着出现。
- **重做上限**：同一张题最多重做 2 次。第 3 次仍错就放过，记入结果页的「仍未掌握」并进入弱项池——避免一个音把整组无限拖长。
- **导航与重定向**：Cloudflare Pages 会把 `/index.html` 用 308 重定向到 `/`，预缓存跟随重定向后存下的是「重定向过的响应」；浏览器禁止用它满足导航请求（会直接 `ERR_FAILED`）。`sw.js` 因此在返回外壳前优先挑未被重定向的条目，必要时重新包一层 Response。`tests/dev/deploy-check.mjs` 的本地服务器也特意复刻了这个 308，避免本地全绿、线上打不开。
- **离线更新**：Service Worker 采用版本化预缓存。`npm run build:static` 会按 `dist/` 内容哈希写入 `CACHE_NAME`，不需要手动改版本；应用检测到新版本时提示「刷新」。
- **无外部请求**：没有字体 CDN、图标 CDN、统计脚本或后端。
